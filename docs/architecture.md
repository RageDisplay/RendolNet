# Архитектура

## Состав узла

```
                ┌───────────────────────── узел: Debian 13 ─────────────────────────┐
                │                                                                   │
  браузер ────▶ │  rendol-api (под, hostNetwork, :443)                              │
  rendolctl     │    REST /v1, веб-интерфейс, ревизии конфига, журнал               │
                │        │                        │                                 │
                │        │ SQL                    │ HTTP по /run/rendolnet/agent.sock│
                │        ▼                        ▼                                 │
                │  Postgres (под)          rendol-agent (DaemonSet, privileged)     │
                │                            netlink: адреса, VLAN, маршруты, DHCP  │
                │                            eBPF: XDP + TC на каждом порту          │
                │                                 ▲                                 │
                │  rendol-zapret (DaemonSet) ─────┘ читает конфиг, держит nfqws     │
                │                                                                   │
                │  rendol-updater (systemd)   обновления, перезагрузка              │
                │  rendol-console (tty1)      адрес, сеть управления, сброс пароля  │
                │  k3s                        всё, что выше в подах                 │
                └───────────────────────────────────────────────────────────────────┘
```

| Компонент | Где работает | За что отвечает |
|---|---|---|
| rendol-agent | под, hostNetwork, privileged | применяет конфиг к ядру, держит таймер подтверждения, отдаёт сессии, счётчики и события |
| rendol-api | под, hostNetwork, порт 443 | веб-интерфейс, API, пользователи, ревизии, журнал, приём пакетов обновления |
| Postgres | под | ревизии, черновик, пользователи, аудит, события, статистика трафика |
| rendol-zapret | под, hostNetwork, NET_ADMIN | nfqws и его правила nftables, когда обход DPI включён |
| rendol-updater | systemd на узле | установка обновлений, перезагрузка и выключение по запросу из веба |
| rendol-console | systemd, tty1 | экран узла: адрес веб-интерфейса, состояние, сеть управления |

## Кто чем владеет

Агент — единственный, кто трогает сеть узла. API в ядро не лезет: он хранит
версии конфига и передаёт агенту готовый документ. Поэтому узел продолжает
фильтровать трафик, когда API, база или k3s лежат.

Агент хранит у себя последнюю подтверждённую ревизию
(`/var/lib/rendolnet/agent/confirmed.json`) и поднимается с ней после
перезагрузки, не дожидаясь API.

Интерфейс управления агент не настраивает. Его адрес задаёт systemd-networkd
(`/etc/systemd/network/10-mgmt.network`): установщик пишет файл, консоль на tty1
его меняет. Так ошибкой в веб-интерфейсе нельзя потерять доступ к узлу.

## k3s

k3s живёт на собственном адресе `10.255.255.1` на dummy-интерфейсе `rnk3s0`
(`iso/rootfs/etc/systemd/network/05-rnk3s.*`, `etc/rancher/k3s/config.yaml`).
От адресов управления и WAN он не зависит: их можно менять, не трогая кластер.

Отключены traefik, servicelb, local-storage, metrics-server, cloud-controller
и helm-controller. Манифесты RendolNet лежат в
`/var/lib/rancher/k3s/server/manifests/`, образы — в
`/var/lib/rancher/k3s/agent/images/`. k3s сам загружает и то, и другое, так что
установка и обновление работают без сети.

API kubernetes (6443) снаружи закрыт политикой: к самому узлу через интерфейс
управления пускаются только порты из раздела «Защита» (по умолчанию 22 и 443).

## Загрузка узла

1. nftables.service загружает `/etc/nftables.conf` — таблицу
   `inet rendolnet_boot`. Она отбрасывает транзит и входящие на WAN и LAN,
   кроме ответов DHCP.
2. Поднимаются systemd-networkd и интерфейс управления, затем k3s.
3. Агент загружает eBPF, применяет сохранённый конфиг и удаляет таблицу
   `rendolnet_boot`. С этого момента фильтрует eBPF.
4. API поднимается, сверяет ревизию в базе с ревизией агента.

Без первого шага между загрузкой ядра и запуском агента узел пропускал бы
трафик насквозь. Таблица не делает `flush ruleset`, чтобы перезапуск nftables
не снёс правила k3s.

## Обмен между API и узлом

У пода API нет прав на хост, кроме двух каталогов:

| Каталог | Зачем |
|---|---|
| `/run/rendolnet` | сокет агента, статус zapret |
| `/var/lib/rendolnet/host` | запросы к rendol-updater (`request.json`), его статус, распакованный пакет обновления, флаг сброса пароля от консоли |

rendol-updater запускает systemd path-юнит, когда появляется `request.json`.

## Хранилище

| Таблица | Что в ней |
|---|---|
| config_revisions | каждая применённая версия конфига целиком, автор, комментарий, состояние |
| candidate | общий черновик, одна строка |
| users, api_tokens | учётные записи; пароли argon2id, токены хранятся хешем |
| audit_log | вход, изменения, применение, обновления |
| events | отбои и сессии из dataplane, срок хранения в настройках |
| traffic | минутные средние скорости по интерфейсам |

Миграции лежат в `internal/platform/db/migrations`, применяются при старте под
advisory-блокировкой, только вперёд.
