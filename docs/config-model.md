# Конфигурация

Конфигурация узла — один JSON-документ (`internal/netcfg/types.go`). Его
целиком хранит каждая ревизия, его же получает агент. Отдельных команд вроде
«добавить правило» в ядро нет: узел всегда приводится к документу целиком.

## Разделы

| Ключ | Что внутри |
|---|---|
| `system` | имя узла, DNS-серверы |
| `zones` | зоны; `self` — сам узел, объявлять не нужно |
| `interfaces` | порты: роль (`wan`, `lan`, `mgmt`), зона, DHCP или адреса, MTU, VLAN |
| `routes` | статические маршруты |
| `objects` | именованные адреса, группы, сервисы |
| `rules` | правила по порядку |
| `nat.source`, `nat.destination` | исходящий NAT и проброс портов |
| `protection` | блок-лист, ограничение SYN, журнал отбоев по умолчанию |
| `management` | интерфейс управления, разрешённые источники, порты |
| `zapret` | обход DPI |

Пример правила:

```json
{
  "id": "r-web",
  "name": "LAN в веб",
  "enabled": true,
  "from": ["lan"],
  "to": ["wan"],
  "source": ["office-net"],
  "destination": [],
  "services": ["web", "udp/443"],
  "action": "allow",
  "log": true
}
```

- `from` и `to` — зоны или `any`. `any` в `from` не включает `self`: трафик,
  который узел отправляет сам, политика не проверяет.
- `source`, `destination` — имена объектов и групп или литералы:
  `192.0.2.7`, `10.0.0.0/8`, `2001:db8::/32`. Пусто — любой адрес.
- `services` — имена сервисов или литералы `tcp/443`, `udp/5000-5010`,
  `icmp`, `icmpv6`. Пусто — любой протокол.
- `action`: `allow`, `deny`, `reject`. Для TCP `reject` отвечает RST, для
  остального работает как `deny`.

Что не подошло ни под одно правило, отбрасывается.

## Проверка

`netcfg.Validate` проверяет документ целиком и возвращает все ошибки сразу с
путями вида `rules[3].services`. Интерфейс подсвечивает по ним строки. Проверка
идёт трижды: при сохранении кандидата (как предупреждение), при применении
(отказ) и в агенте (отказ). Последняя страхует от того, что в агент пришло
что-то в обход API.

## Кандидат и ревизии

```
правки в интерфейсе ──▶ кандидат ──(применить)──▶ ревизия rN ──▶ агент
                          ▲                           │
                          └──(загрузить в кандидат)───┘
```

- Кандидат один на систему: правки разных администраторов видны друг другу.
  Если кандидат поменяли, пока вы его редактировали, сохранение вернёт 409 и
  имя того, кто правил.
- Применение создаёт ревизию с полным телом конфига, автором и комментарием.
- Откат — это обычное применение: старая ревизия загружается в кандидат и
  применяется заново, в истории появляется новая ревизия.

| Состояние ревизии | Значит |
|---|---|
| `imported` | начальная: конфиг, с которым узел пришёл из установщика |
| `pending` | применена, ждёт подтверждения |
| `committed` | действует |
| `rolled_back` | не подтверждена вовремя, узел вернул предыдущую |
| `failed` | агент не смог применить |

## Подтверждение

При применении можно задать время на подтверждение (по умолчанию 2 минуты,
меняется в «Системе»). Пока оно не вышло, наверху каждой страницы висит полоса
с обратным отсчётом и кнопкой «Подтвердить».

Таймер держит агент, а не API. Если после применения пропал доступ к
веб-интерфейсу, подтвердить невозможно, и агент сам вернёт предыдущую ревизию,
даже если API в этот момент недоступен. После перезагрузки узла в середине
проверки агент поднимается с последней подтверждённой ревизией: неподтверждённая
не восстанавливается.

API раз в 5 секунд сверяется с агентом: отмечает откаченные ревизии и, если
агент работает не с последней подтверждённой (например, его состояние
стёрли), отправляет её заново.

## Стартовый конфиг

Установщик пишет агенту `netcfg.Default`:

- зоны `wan`, `lan`, `mgmt`;
- маскарад для LAN через WAN;
- правила: LAN в WAN — разрешить; LAN к узлу — DNS и ping; ping снаружи — выключено;
- доступ к управлению — порты 22 и 443 на интерфейсе управления;
- журнал отбоев по умолчанию включён.

Без ISO тот же конфиг задаётся переменной агента `RN_SEED`:

```
RN_SEED=hostname=fw1,mgmt=eth0,wan=eth1,lan=eth2,lan_addr=192.168.1.1/24
```

`wan_addr=203.0.113.2/24` и `gateway=203.0.113.1` вместо DHCP на WAN.
Применяется, только если подтверждённого конфига ещё нет.
