# Dataplane

Весь код фильтрации — `bpf/rendol.c`, одна объектная сборка из трёх программ.
Go-обвязка генерируется bpf2go в `internal/dataplane/ebpf/` и лежит в
репозитории, поэтому Go собирается без clang. После правки C-кода:

```
make bpf        # перегенерировать обвязку (в контейнере с clang)
make test-bpf   # прогнать программы в настоящем ядре
```

Требования к ядру: 6.6 и новее (TCX). Debian 13 — 6.12.

## Программы

| Программа | Точка | Что делает |
|---|---|---|
| `xdp_guard` | XDP на каждом порту | блок-лист (LPM по адресу источника), ограничение SYN на источник |
| `tc_ingress` | TCX ingress | обратный NAT, DNAT, conntrack, политика, RST для «отклонить» |
| `tc_egress` | TCX egress | маскарад и SNAT, conntrack для трафика самого узла |

XDP ставится в нативном режиме, если драйвер умеет, иначе в общем
(`generic`). Режим виден на странице «Система».

## Путь пакета через узел

```
порт ─▶ XDP: блок-лист, SYN ─▶ TC ingress ─────────────────────────▶ стек ядра ─▶ TC egress ─▶ порт
                                 │ 1. адресован нам и есть в snat_rev?  │ маршрутизация
                                 │    → вернуть исходный адрес/порт     │
                                 │ 2. сессия есть в ct? → пропустить     │
                                 │ 3. проброс порта (dnat)? → подменить  │
                                 │ 4. новая: зона входа, зона выхода     │
                                 │    по bpf_fib_lookup, правила пары    │
                                 │    зон, запись в ct                   │
```

Маршрутизирует ядро. eBPF только решает, пустить ли пакет, и переписывает
адреса. `bpf_fib_lookup` нужен, чтобы ещё на входе знать зону выхода. Пакеты
к самому узлу получают зону `self`.

Интерфейсы, на которых агента нет (cni0, flannel, veth подов), считаются
частью узла: для политики это тоже `self`.

## Карты

| Карта | Тип | Назначение |
|---|---|---|
| `ct` | LRU hash, 262144 | сессии; ключ — исходный 5-tuple |
| `snat_rev` | LRU hash, 131072 | обратное отображение порта NAT на внутренний адрес |
| `ifaces` | hash | ifindex → зона, роль, IPv4-адрес интерфейса |
| `rules` | array, 2×4096 | правила, развёрнутые по парам зон |
| `pairs` | hash | (банк, зона из, зона в) → диапазон в `rules` |
| `addr_sets` | LPM trie | наборы адресов правил; ключ — номер набора + адрес |
| `bankcfg`, `active` | array | настройки банка, номер действующего поколения |
| `dnat`, `snat_rules` | hash, array | проброс портов и правила исходящего NAT |
| `blocklist`, `syn_rl` | LPM trie, LRU hash | XDP |
| `rule_stats`, `stats` | per-CPU array | счётчики правил и общие |
| `events` | ringbuf, 4 МБ | отбои и разрешения для журнала |

`ct` и `snat_rev` закреплены в `/sys/fs/bpf/rendolnet`. Связи программ с
интерфейсами тоже закреплены, поэтому перезапуск пода агента ничего не рвёт:
новый агент берёт закреплённые карты и подменяет программу в существующей
связи.

Если формат закреплённой карты поменялся между версиями, агент её
пересоздаёт. Установленные сессии при этом теряются, а новые проходят по
политике как обычно.

Адреса в картах хранятся в 16 байтах; IPv4 — как `::ffff:a.b.c.d`. Так у
v4 и v6 один код и один набор карт.

## Политика и атомарная замена

Компилятор (`internal/dataplane/compile.go`) раскрывает правила по всем парам
зон и сервисам: правило «lan → any, tcp/80,443» превращается в записи для
каждой пары (lan, X) и каждого диапазона портов. В пределах пары сохраняется
порядок правил. Предел — 4096 записей на банк.

Банков два. Агент пишет новую политику в неактивный банк, затем одной записью
меняет номер поколения в `active`. Программа читает номер банка один раз на
пакет, поэтому пакет никогда не видит половину старой политики и половину новой.

У каждой сессии записано поколение, при котором её разрешили. Если политику
сменили, первый пакет старой сессии в прямом направлении проверяется заново.
Сессия, которую новая политика запрещает, удаляется. Так запрет начинает
действовать сразу, а не после того, как все соединения закроются сами.

Перебор правил идёт через `bpf_loop`, верификатор не ограничивает длину списка.

## Conntrack

Состояния TCP упрощены: SYN_SENT → ESTABLISHED после ответа и ACK, FIN, CLOSE
по RST. Таймауты:

| Состояние | Таймаут |
|---|---|
| syn_sent | 60 с |
| established | 1 ч |
| fin | 120 с |
| close | 10 с |
| udp | 120 с |
| icmp | 30 с |

TCP-сессии подхватываются с середины, если политика их разрешает: после
перезагрузки узла уже открытые соединения не обрываются. Так же ведёт себя
conntrack ядра с `nf_conntrack_tcp_loose=1`.

Агент каждые 15 секунд проходит по `ct`, удаляет просроченное и освобождает
порты NAT. Для сессий с правилами с журналированием он пишет событие о закрытии.

## NAT

Только IPv4.

- Маскарад и SNAT — на выходе (`tc_egress`). Порт берётся из диапазона
  41000–65535. Диапазон 32768–40999 агент оставляет ядру для собственных
  соединений узла (`net.ipv4.ip_local_port_range`), чтобы порты не пересекались.
  Если исходный порт уже в верхнем диапазоне и свободен, он сохраняется.
- Проброс портов — на входе (`tc_ingress`), с адреса входного интерфейса.
  Ответы сервера переписываются обратно по записи в `ct`.
- Ping через маскарад работает: идентификатор эха транслируется как порт.

Не поддерживается: hairpin NAT (обращение к внешнему адресу изнутри той же
сети), NAT для IPv6.

## Особые случаи

- ICMP-ошибки (unreachable, time exceeded, parameter problem, packet too big)
  пропускаются без сессии.
- Соседство IPv6 (ICMPv6 133–137) пропускается всегда.
- Ответы DHCP-сервера (UDP 67 → 68, 547 → 546) к узлу пропускаются всегда:
  они приходят раньше, чем у WAN появится адрес.
- Нефрагментированный и первый фрагмент проверяются как обычно, последующие
  фрагменты пропускаются: у них нет портов, а без первого фрагмента
  получатель их не соберёт.
- Тегированные кадры на родительском интерфейсе пропускаются, их проверит
  VLAN-интерфейс со своей зоной.
- Доступ к управлению (порты из раздела «Защита» на интерфейсе управления)
  проверяется до правил.

## Тесты

`internal/dataplane/bpf_linux_test.go` поднимает dummy-интерфейсы в отдельном
сетевом пространстве и гоняет программы через `BPF_PROG_TEST_RUN`: маскарад с
проверкой контрольных сумм, проброс портов, RST, ping через NAT, IPv6, XDP,
пересмотр сессий при смене политики.
