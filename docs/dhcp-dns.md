# DHCP-сервер и DNS-прокси

Обе службы работают внутри агента (`internal/dhcpd`, `internal/dnsfwd`) и
настраиваются в общем конфиге, поэтому на них действуют черновик, подтверждение
и откат. В интерфейсе — раздел «DHCP и DNS».

## DHCP-сервер

Включается на интерфейсе с ролью `lan` и статическим IPv4-адресом:

```json
"dhcp_server": {
  "enabled": true,
  "range_start": "192.168.1.100",
  "range_end": "192.168.1.199",
  "lease_minutes": 720,
  "dns": [],
  "domain": "lan",
  "static": [{"mac": "02:00:00:00:00:99", "address": "192.168.1.50", "name": "printer"}]
}
```

| Опция клиенту | Значение |
|---|---|
| шлюз, server id | первый IPv4-адрес интерфейса |
| маска | маска этого адреса |
| DNS | `dns`; если пусто — адрес узла при включённом DNS-прокси, иначе `system.dns` |
| срок аренды | `lease_minutes`, по умолчанию 12 часов |

Как выбирается адрес для клиента:
1. Привязка по MAC.
2. Прежний адрес клиента.
3. Адрес, который клиент просит сам.
4. Первый свободный адрес диапазона: сначала ни разу не выданные, потом истёкшие.

Адрес, от которого клиент отказался (DHCPDECLINE, кто-то занял его вручную),
не выдаётся на срок одной аренды. На запрос адреса из чужой сети или занятого
адреса сервер отвечает NAK, и клиент начинает заново.

Аренды сохраняются в `/var/lib/rendolnet/agent/dhcp-leases.json`, и после
перезапуска агента клиенты получают прежние адреса. Сервер перезапускается,
только если изменились его собственные настройки.

Установщик включает сервер на каждой LAN с диапазоном .100–.199 в /24, где
стоит адрес узла. Если узел сам стоит в этом диапазоне, берётся .10–.99. В
сетях мельче /24 сервер включают вручную.

### Пропуск в eBPF

Запрос клиента идёт с 0.0.0.0 на 255.255.255.255:67, и политика зон для него
не подходит. `tc_ingress` пропускает в стек UDP 68→67, если адрес назначения
широковещательный или принадлежит узлу (продление). DHCP транзитом к чужому
серверу этим исключением не пользуется и проходит по политике.

## DNS-прокси

`dns_proxy.enabled` открывает UDP и TCP порт 53 на адресах узла во всех LAN.
Запросы пересылаются серверам из `system.dns` по очереди, пока один не
ответит. Пусто — 1.1.1.1 и 8.8.8.8. Кэша нет, ответ возвращается как есть.

Доступ клиентов к порту 53 узла даёт стартовое правило «LAN к узлу: DNS и
ping». Если оно выключено, DNS-прокси снаружи не виден.

## Объекты по доменам

У объекта адресов, кроме сетей, может быть список доменов:

```json
{"name": "tiktok", "prefixes": [], "domains": ["tiktok.com", "tiktokcdn.com"]}
```

Такой объект подставляется в правила как обычный, например «`lan2` → `wan`,
назначение `tiktok`, запретить». Домен включает поддомены, `*.` в начале
можно не писать.

Как адреса попадают в правило:

1. Компилятор отдаёт агенту `DomainSets`: в каких наборах eBPF стоит домен.
2. DNS-прокси перед отдачей ответа клиенту вызывает `Agent.ObserveDNS`.
   Агент берёт из ответа все имена (вопрос, владельцев записей, цели CNAME) и
   все A/AAAA. Если хоть одно имя подходит под домен, адреса добавляются в его
   наборы действующего банка (`Dataplane.SetAddr`). Клиент получает ответ уже
   после этого, поэтому первое же соединение попадает под правило.
3. Адрес живёт TTL записи, не меньше минуты и не больше суток, плюс 10 минут
   запаса на кэш клиента. Просроченные адреса убираются раз в 30 секунд, если
   их не держит другой домен того же набора или сам конфиг.
4. При каждом применении конфига выученные адреса дописываются в план, иначе
   смена банка их бы стёрла.
5. Раз в 5 минут и после применения агент сам разрешает домены объектов
   через `system.dns`. Так в объект попадают адреса, которые клиент взял из
   своего кэша и больше не спрашивает.

Выученные адреса видны в «Объектах» и по `GET /v1/diag/fqdn`.

Ограничения, о которых надо помнить:

- Клиент должен спрашивать DNS у узла. Если на нём вручную прописан 8.8.8.8,
  адреса в объект не попадут. Чтобы обойти правило было нельзя, запретите
  LAN ходить на порт 53 наружу (`lan → wan`, `udp/53`, `tcp/53`, запретить).
- DNS поверх HTTPS (DoH) в браузере идёт мимо узла. Chrome включает его сам,
  когда системный DNS — публичный сервер с поддержкой DoH (8.8.8.8, 1.1.1.1).
  С DNS узла автоматического DoH не бывает, но явно включённый в браузере
  обходит правило.
- На одном адресе CDN живут тысячи сайтов. Запрет домена на CDN режет и
  соседей, пока адрес в наборе.
