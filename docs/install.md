# Установка

## Требования

| | Минимум | Заметки |
|---|---|---|
| Процессор | x86-64, 2 ядра | |
| Память | 2 ГБ | k3s, Postgres и API занимают около 1 ГБ |
| Диск | 8 ГБ | весь диск отдаётся системе |
| Сетевые порты | 1 | управление; для работы маршрутизатором — ещё WAN и LAN |
| Загрузка | UEFI или BIOS | Secure Boot не поддерживается |

Нативный XDP есть у большинства серверных карт (Intel ixgbe/i40e/ice, Mellanox
mlx5, virtio-net). На остальных XDP работает в общем режиме: медленнее, но
функции те же.

Работает в Proxmox, VMware, Hyper-V и на железе. Гостевые агенты для всех
трёх установлены.

## Установка с ISO

1. Запишите `rendolnet-<версия>-amd64.iso` на флешку (dd, Rufus в любом
   режиме, Ventoy) или подключите как CD.
2. Загрузитесь и выберите «Install RendolNet».
3. Выберите системный диск. Диски с данными предлагаются, только если ввести
   их серийный номер. Установочный носитель и смонтированные диски не
   предлагаются вовсе.
4. Раздайте роли сетевым портам: стрелки ←→ меняют роль у выбранного порта.
   - **управление** — обязателен, на нём будет веб-интерфейс;
   - **WAN** — внешний канал, к нему применяется маскарад;
   - **LAN** — внутренняя сеть, ей разрешён выход наружу.
5. Адрес управления: DHCP или статический. Шлюз управления получает метрику
   2048 и используется, только когда нет WAN: иначе интернет-трафик LAN ушёл
   бы через сеть управления.
6. WAN: DHCP или статический адрес. LAN: адрес с маской, по умолчанию
   `192.168.1.1/24`.
7. Имя узла, часовой пояс, ключ SSH (необязательно; без него SSH выключен).
8. Подтвердите. Установка занимает 2–5 минут, журнал — `/run/rendol-installer.log`.

После перезагрузки на tty1 появится консоль узла с адресом веб-интерфейса.
Первый запуск k3s и загрузка образов занимают ещё 1–2 минуты.

Вход: **admin / admin**. Политики паролей пока нет; смените пароль в разделе
«Пользователи».

## Что делает установщик

Разметка GPT: ESP 512 МБ, BIOS boot 1 МБ, остальное — ext4. Система
копируется из squashfs, затем записываются:

| Файл | Содержимое |
|---|---|
| `/etc/systemd/network/10-mgmt.network` | адрес управления |
| `/etc/nftables.conf` | загрузочная защита для WAN и LAN, см. [architecture.md](architecture.md) |
| `/var/lib/rendolnet/agent/confirmed.json` | стартовый конфиг |
| `/var/lib/rancher/k3s/server/manifests/rendolnet-local.yaml` | случайный пароль Postgres |

Включаются: systemd-networkd, nftables, k3s, rendol-updater.path,
rendol-console. GRUB ставится и для UEFI, и для BIOS.

## Автоустановка

1. Создайте том с меткой `RNAUTO` (FAT или ext4) и положите на него
   `autoinstall.yaml`. Пример — [iso/autoinstall.example.yaml](../iso/autoinstall.example.yaml).
2. В меню загрузки выберите пункт «autoinstall».

Без этого пункта меню файл игнорируется: забытая в сервере флешка ничего не
сотрёт. Диск в файле указывается путём by-id; если на нём есть данные, нужен
ещё `confirm` с серийным номером. При ошибке установщик останавливается и не
повторяет попытку сам.

## Консоль узла

На tty1 установленного узла:

- адрес веб-интерфейса и состояние k3s, API и dataplane;
- **Сеть управления** — сменить адрес, не заходя в веб;
- **Сбросить пароль admin** — пароль станет `admin`, пользователь будет
  разблокирован (физический доступ считается достаточным правом);
- перезагрузка, выключение, командная оболочка.

## Без ISO

На готовом Debian 13 с k3s:

```
kubectl apply -f deploy/k8s/secret.example.yaml   # поправьте пароль и seed
bash scripts/render-manifests.sh <версия> | kubectl apply -f -
```

Интерфейсы, адрес k3s и загрузочную защиту в этом случае настраиваете сами,
см. файлы в `iso/rootfs/etc`.
